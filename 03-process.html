Program = สูตรอาหารวางอยู่บนชั้นหนังสือ (ไม่ขยับ ไม่กินทรัพยากร) · Process = คนกำลังทำอาหารตามสูตรนั้นในครัว (ใช้เตา ใช้จาน ใช้เวลา — 1 สูตรเดียวทำซ้ำหลายคนได้ คนละ process!)

2. สถานะของ Process (Process States)

Process หนึ่งตัวตลอดชีวิตเดินไปมาระหว่างสถานะ แบบพื้นฐาน 5 สถานะ (ใน handout ใช้ Seven-state model เพิ่ม suspended อีก 2):

🎯 จุดหลอกข้อสอบ

Process ที่จบ I/O ไปรอที่ Ready ก่อน ไม่ได้กลับเข้า Running ทันที — ต้องรอ dispatcher เรียกใหม่ (เพราะ CPU อาจมีคนใช้อยู่)

Seven-State Model (เพิ่มเรื่อง suspend)

เมื่อ RAM ตึงตัว ระบบอาจ "swap out" process ที่รออยู่ไปพักบนดิสก์ ทำให้มีสถานะเพิ่มอีก 2: Suspended Ready (พร้อมรันแต่ถูกย้ายออกจาก RAM) และ Suspended Blocked (กำลังรอ event แล้วก็ถูกย้ายออกด้วย) รวมเป็น 7 สถานะ

3. Scheduling Queues และ PCB

OS จัด process เป็นคิว 3 แบบ:

  • Job queue — process ทุกตัวในระบบ
  • Ready queue — ตัวที่อยู่ใน RAM พร้อมรัน รอ CPU
  • Device queues — ตัวที่รออุปกรณ์ I/O แต่ละชนิด (คิวรอพรินเตอร์ก็มีคิวตัวเอง รอดิสก์ก็มีของตัวเอง)

Process เดินย้ายคิวไปมาตลอดชีวิต และข้อมูลทั้งหมดของมันถูกเก็บใน "รหัสประชาชน" ที่เรียกว่า PCB (Process Control Block):

Process state Program counter (PC) CPU registers Scheduling info (priority, queue) Memory info (base/limit) Accounting info I/O status

4. Context Switch

เมื่อ CPU จะเปลี่ยนจาก process A ไป process B: OS ต้อง เซฟ state เดิมของ A เข้า PCB ของ A แล้ว โหลด state ของ B จาก PCB ของ B กลับเข้า CPU — ช่วงเวลานี้เรียกว่า context switch

⚠️ สำคัญกับความเข้าใจเรื่อง overhead

ช่วง context switch เป็น pure overhead — ระบบไม่ได้ทำงานที่มีประโยชน์เลยแม้แต่วินาทีเดียว เวลาที่ใช้ขึ้นกับฮาร์ดแวร์ที่ช่วยได้แค่ไหน (เช่น register หลายชุด) — ประเด็นนี้จะกลับมาตอนเลือก time quantum ใน Round Robin (บท 5)

Dispatcher

Dispatcher คือ "คนขับส่ง" ที่รับ process จาก short-term scheduler แล้วทำ 3 อย่าง:

  1. Switching contextสลับ context (เซฟเก่า โหลดใหม่)
  2. Switching to user modeเปลี่ยนจาก kernel mode กลับเป็น user mode
  3. Jump ไปตำแหน่งเดิมกระโดดไปที่ address ใน user program เพื่อรันต่อจากเดิม

Dispatch latency = เวลาที่ dispatcher ใช้หยุด process หนึ่งและเริ่มอีก process หนึ่ง

6. fork() — สร้าง process แบบ "โคลนตัวเอง" 🔥

ใน UNIX parent process สร้างลูกด้วย fork() — มันจะ ก๊อปปี้ตัวเองออกมาเป็น child แล้วทั้งคู่รันต่อจากบรรทัดเดียวกัน (บรรทัดหลัง fork)

fork.h
#include <sys/types.h>
#include <unistd.h>
pid_t fork(void);  // สร้าง child โดยก๊อปปี้ parent

เวทมนตร์อยู่ที่ค่า return ที่ต่างกันในสองโลก:

ใครเรียกค่าที่ fork() คืนให้เงื่อนไข if ที่จะเข้า
ใน ParentPID ของลูก (เลขบวก > 0)if (pid > 0)
ใน Child0else if (pid == 0)
สร้างไม่สำเร็จค่าลบ (< 0)if (pid < 0) → error
📌 สิ่งที่ลูกได้รับ (จำไว้เจอข้อหลอก)

ตัวแปร (เช่น int i) ถูกก๊อปปี้ไปให้ลูก — แก้ในฝั่งไหนไม่กระทบอีกฝั่ง (คนละ copy) · แต่ข้อความพิมพ์ออกจอด้วยกัน · ลำดับการพิมพ์ parent/child เป็น non-deterministic — ไม่มี wait() อย่าเถียงว่าใครพิมพ์ก่อน!

7. ไล่โค้ด fork ทีละบรรทัด (ตัวอย่างจากวิดีโออาจารย์)

fork_example.c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

int main() {
    pid_t pid;
    int i = 0;
    pid = fork();                      // ← จุดแตกหน่อ
    if (pid > 0) {   /* parent */
        i = 1;
        printf("I am parent i = %d\n", i);
    }
    else {           /* child */
        i = 2;
        printf("I am child i = %d\n", i);
    }
    return 0;
}
  1. บรรทัด pid = fork();ก่อนบรรทัดนี้มี 1 process หลังบรรทัดนี้มี 2 process (parent + child) — ทั้งคู่ถือ copy ของตัวแปร pid กับ i ของตัวเอง
  2. ฝั่ง Parentได้ pid = PID ของลูก (> 0) → เข้า if บน → ตั้ง i = 1 → พิมพ์ "I am parent i = 1"
  3. ฝั่ง Childได้ pid = 0 → เข้า else → ตั้ง i = 2 → พิมพ์ "I am child i = 2"
  4. ผลรวมพิมพ์ออกมา 2 บรรทัดเสมอ (ไม่ใช่ 1!) แต่ลำดับก่อนหลังสลับกันได้ตามใจ scheduler

ตัวอย่าง fork + loop จากวิดีโอ (มี exit ใน child)

loop_fork.c (โครงจากวิดีโอ 3.4)
for (i = 0; i < 5; i++) {          // parent วน 5 รอบ
    pid = fork();
    if (pid == 0) {                  // ลูกเท่านั้น
        if (i % 2 != 0)
            printf("I am happy\n");  // ลูกที่เกิดตอน i คี่
        else
            printf("I am sad\n");    // ลูกที่เกิดตอน i คู่
        exit(0);                     ← สำคัญ! ลูกจบตัวเองทันที
    }
}
while (wait(NULL) != -1);            // parent รอลูกทุกตัว
printf("I am parent goodbye\n");

ผลลัพธ์: I am sad ×3 (ลูกที่เกิดตอน i = 0, 2, 4) · I am happy ×2 (i = 1, 3) · และ I am parent goodbye 1 ครั้ง เป็นบรรทัดสุดท้ายเสมอ (เพราะ wait รอให้ลูกครบ 5 ก่อน)

🚨 จุดหลอกคลาสสิกของอาจารย์: ถ้าลูกเลขคี่ "ลืม exit()"

ลูกที่พิมพ์ happy เสร็จไม่ได้ตาย — มันหลุดออกจาก if แล้ววนลูป for ต่อเหมือนพ่อ ไปสร้างลูก/หลานของตัวเองเพิ่ม! ผลคือเกิด process ซ้อนกันมั่ว และข้อความ goodbye พิมพ์ออกมา 4 ครั้ง (จาก parent หลัก 1 + ลูกที่กลายเป็น "พ่อ" อีก 3 ตัว: C₁, C₃ และหลาน C₁₋₃) — เวลาไล่โค้ด ต้องถามตัวเองทุก fork ว่า "สายไหนรันบรรทัดนี้อยู่ และใครจบตัวเองบ้าง"

8. นับจำนวน Process — สูตร 2ⁿ + วิธีวาดต้นไม้

fork() ติดกัน n ครั้ง (ไม่มีเงื่อนไข/ไม่มี exit) → Process ทั้งหมด = 2ⁿ ตัว (ลูกใหม่ = 2ⁿ − 1 ตัว)เช่น fork(); fork(); fork(); → ทั้งหมด 8 process (parent 1 + ลูกใหม่ 7)

ถ้ามีเงื่อนไขพันกัน ให้วาด Process Tree — ทุกครั้งที่สายไหนใด ๆ ผ่าน fork() ให้แตกกิ่งออกมาหนึ่งกิ่ง แล้วเช็คว่ากิ่งไหนโดน exit() หรือหลุดลูป

9. exec() — เปลี่ยนร่าง ไม่ได้สร้างคนใหม่

exec() เป็นตระกูลฟังก์ชัน (execlp, execv ฯลฯ) ที่ทำหน้าที่ แทนที่ process image ปัจจุบันด้วยโปรแกรมใหม่ทั้งหมด — process เดิมยังเป็น PID เดิม แต่ "วิญญาณ" (โค้ด+data) ถูกเปลี่ยนไปเป็นโปรแกรมอื่นเฉย ๆ

รูปแบบ execlp
execlp("ls", "ls", "-l", NULL);
//      └file └arg0 └arg1  └NULL ปิดท้ายบังคับ
  • l = List — ส่งพารามิเตอร์เรียงทีละตัว (ส่วน v = Vector ส่งเป็น array)
  • p = PATH — ให้ OS ตามหาโปรแกรมตาม environment variable PATH ไม่ต้องพิมพ์ full path (พิมพ์แค่ "ls" ก็พอ)
  • arg0 — ธรรมเนียม C ใส่ชื่อโปรแกรม (exec ไม่สนใจตัวนี้ แต่ต้องใส่ไว้)
  • NULL — ตัวปิดท้าย บังคับใส่เสมอ
🚨 จุดหลอกสำคัญที่สุดของ exec

โค้ดบรรทัดที่อยู่หลัง exec() (ถ้า exec สำเร็จ) จะไม่ถูกรันเด็ดขาด — เพราะ process image เดิมถูกทับหมดแล้ว! แต่ถ้า exec ล้มเหลว (เช่นพิมพ์ชื่อผิดเป็น "ly") โค้ดจะวิ่งไปบรรทัดถัดไปตามปกติ (เช่น พิมพ์ "I'm child")
แถมอีกจุด: exec("cd", ...) จะ error เพราะ cd เป็น shell built-in ไม่ใช่ไฟล์โปรแกรม หาไม่เจอใน PATH (ส่วน echo รันได้เพราะมีไฟล์ /usr/bin/echo)

โครงสร้าง fork + exec (รูปแบบมาตรฐาน — shell ใช้แบบนี้)

fork_exec.c (จาก handout)
int main() {
    pid_t pid;
    pid = fork();
    if (pid < 0) {                 /* error */
        fprintf(stderr, "Fork Failed");
        exit(-1);
    }
    else if (pid == 0) {           /* child */
        execlp("/bin/ls", "ls", NULL);   // ลูกเปลี่ยนร่างเป็น ls
    }
    else {                         /* parent */
        wait(NULL);                 // พ่อรอลูกเสร็จก่อน
        printf("Child Complete");
        exit(0);
    }
}

Output: รายการไฟล์ใน directory (จาก ls) ตามด้วย Child Complete — ลำดับแน่นอนเพราะ parent wait() ก่อนพิมพ์

10. exit(), wait(), waitpid() — ปิดงานให้เรียบร้อย

  • exit(status) — process ร้องขอให้ OS ทำลายตัวเอง พร้อมส่ง status กลับให้ parent (ส่งได้แค่ 8-bit: 0–255) ทรัพยากรทั้งหมดถูก OS คืน
  • wait(NULL) — parent หยุดรอจนกว่าลูกตัวใดตัวหนึ่งจบ ไม่สนค่า status คืน PID ของลูกที่เพิ่งจบ · ถ้าไม่มีลูกเหลือให้รอ → คืน -1 (เลยมี trick: while (wait(NULL) != -1); = รอลูกทุกตัว)
  • waitpid(pid, &status, 0) — รอลูกตัวเจาะจงตาม PID ที่ระบุ (เลข 0 คือโหมด blocking ปกติ) ทำให้ parent รายงานผล "เรียงลำดับ" ได้ ต่างจาก wait() ที่ได้ใครมาก่อนได้ก่อน
  • WIFEXITED(status) / WEXITSTATUS(status) — แมโครตรวจว่าลูกจบแบบปกติไหม และดึงค่า exit จริงออกมา (พิมพ์ status ตรง ๆ จะได้เลขแปลก ๆ เช่น 32768 เพราะในนั้น OS แปะข้อมูลอื่นปนอยู่!)

โค้ดที่มี fork() หนึ่งครั้งใน main โดยไม่มี wait() เลย — เราสามารถสรุปได้แน่นอนว่า parent จะพิมพ์ข้อความก่อน child เสมอ
กถูก
ขผิด
เฉลย: ผิดลำดับการรันหลัง fork เป็น non-deterministic ขึ้นอยู่กับ CPU scheduler — ถ้าไม่มีกลไกซิงก์เช่น wait() ห้ามสรุปใครก่อน-หลังเด็ดขาด (และจำไว้: โค้ดข้อสอบ compile ผ่านหมด ไม่มีตอบ Error)
✏️ข้อ 6เติมตัวเลข — จุดหลอกจากวิดีโอ!
for (i = 0; i < 5; i++) {
    pid = fork();
    if (pid == 0) {
        if (i % 2 != 0) printf("I am happy\n");
        else            printf("I am sad\n");
        // exit(0); ← ลูกเลขคี่ "ลืม" บรรทัดนี้ (เฉพาะเคสคี่)
    }
}
while (wait(NULL) != -1);
printf("I am parent goodbye\n");
ถ้าลูกเลขคี่ (เกิดตอน i = 1, 3) พิมพ์ happy แล้วไม่มี exit() จะทำให้ข้อความ "I am parent goodbye" ถูกพิมพ์รวมกี่ครั้ง (ตามที่อาจารย์สาธิตในวิดีโอ)
เฉลย: 4 ครั้งลูกเลขคี่ C₁, C₃ พิมพ์เสร็จไม่ตาย หลุดไปวนลูป for ต่อแล้ว fork ลูกของตัวเอง (เกิดหลาน เช่น C₁₋₃) ตัวที่พิมพ์ goodbye คือ "พ่อ" ทุกตัวที่รอลูกจนครบ: parent หลัก + C₁ + C₃ + C₁₋₃ = 4 ครั้ง นี่คือเหตุผลที่ลูกต้อง exit() ทุกครั้งที่ทำงานเสร็จในลูป
