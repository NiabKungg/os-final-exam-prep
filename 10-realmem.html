1. Logical vs Physical Address + MMU

Logical Address (Virtual Address)Physical Address
ใครสร้างCPU ปล่อยออกมาขณะรันโปรแกรมตำแหน่งจริงที่ "หน่วยความจำ" มองเห็น
จุดอ้างอิงมองว่าโปรแกรมเริ่มที่ byte ที่ 0 เสมอเทียบกับจุดเริ่มของ RAM จริง

MMU (Memory Management Unit) = ฮาร์ดแวร์แปลง logical → physical แบบง่ายสุดคือใช้ Relocation Register (Base Register) เก็บตำแหน่งที่ OS โหลดโปรแกรมลง RAM:

Physical Address = Relocation Register + Logical Addressตัวอย่างวิดีโอ: โปรแกรมถูกโหลดที่ RAM ตำแหน่ง 14,000 — CPU ขอ byte ที่ 346 → Physical = 14,000 + 346 = 14,346
🏨 เปรียบเทียบ

Logical address = "เลขห้อง 305 ชั้น 3 ในโรงแรม" (เทียบกับตัวตึก) · Physical address = "พิกัดจริงบนแผนที่เมือง" · MMU = นายหน้าแปลงเลขห้องให้เป็นพิกัด — คุณ (โปรแกรม) ไม่จำเป็นต้องรู้เลยว่าตึกอยู่ถนนไหน (โปรแกรมไม่เคยเห็น physical address เลย)

2. Static vs Dynamic Linking — ตัวอย่างเลขจากวิดีโอ

Static linking: ก๊อปโค้ด library มารวมในไฟล์โปรแกรมตั้งแต่ compile — Dynamic linking: เลื่อนการเชื่อมไปตอนรัน ใส่แค่ stub (โค้ดจิ๋วที่ไปหา library แทน แล้วแทนตัวเองด้วย address ของ routine ที่หาเจอ) ทำให้ library ถูกแชร์ร่วมกันได้ (shared libraries)

สถานการณ์ (ตัวอย่างวิดีโอ)Static LinkingDynamic Linking
โปรแกรม A (10 MB) + Lib (20 MB)ไฟล์ A = 30 MBA = 10 + stub 2 = 12 MB
โปรแกรม B (20 MB) + Lib ตัวเดียวกันไฟล์ B = 40 MBB = 20 + stub 2 = 22 MB
RAM รวมเมื่อรันทั้งคู่30 + 40 = 70 MB (Lib โหลดซ้ำ 2 ชุด!)12 + 20 + 22 = 54 MB (Lib โหลดครั้งเดียว แชร์กัน)

ประหยัดไป 16 MB — stub จะเช็คว่า lib อยู่ใน RAM หรือยัง ถ้ายังไม่มีค่อยโหลด ถ้ามีแล้วใช้ร่วมทันที (OS ช่วยเช็คว่า routine นั้นอยู่ใน address space ของ process หรือไม่)

3. Fixed Partition — แบ่งช่องล่วงหน้าคงที่

แบ่ง RAM ส่วนผู้ใช้เป็นช่องขนาดคงที่ตั้งแต่ก่อนเปิดเครื่อง — มีกี่ partition รองรับ process พร้อมกันได้แค่นั้น การป้องกันใช้ Limit Register (ขนาดช่อง) + Relocation Register (ตำแหน่งเริ่มช่อง): CPU ออก logical address → เช็คว่า LA < Limit ไหม ผ่านค่อย + Relocation

ตัวอย่างจากวิดีโอ: partitions 4 ช่อง: P1 (100K), P2 (25K), P3 (25K), P4 (50K) — งานเข้ามาตามลำดับ:

งานผลการจัดสรรเศษทิ้ง (Internal Fragmentation)
Job 1 (30K)ลง P1 (100K)70K ว่างในช่องแต่ใช้ไม่ได้
Job 2 (50K)ลง P4 (50K) พอดี0
Job 3 (30K)ต้องรอ! 😱P2, P3 มีแค่ 25K เล็กเกินไป แม้รวมที่ว่างเหลือ 70+25+25 = 120K
Job 4 (25K)ลง P2 (25K) พอดี0
Fixed Partition → เกิด Internal Fragmentation"เศษใน" — พื้นที่ว่างที่ติดอยู่ในช่องที่ถูกจองแล้ว ใครก็เอาไปใช้ต่อไม่ได้

4. Variable Partition — จัดตามขนาดจริง

ไม่แบ่งล่วงหน้า งานมาเท่าไรตัดให้เท่านั้น — ตอนแรกไม่มีของเสียเลย แต่พองานเก่าจบทิ้งช่องว่างกระจัดกระจาย เกิด External Fragmentation ("เศษนอก" — รวม ๆ ว่างเยอะแต่ช่องเดี่ยวเล็ก)

ตัวอย่างวิดีโอ: ช่องว่างเหลือ 5 MB, 2 MB, 1 MB (รวม 8 MB) — งานใหม่ต้องการ 7 MB → โหลดไม่ได้! เพราะไม่มีช่องเดียวใหญ่พอ

Job A ว่าง 5MB Job B ว่าง 2MB Job C ว่าง 1MB รับ 7MB ไม่ได้ (ช่องใหญ่สุดแค่ 5MB)

วิธีรักษา external fragmentation มี 2 ทาง:

  • Coalescing — รวมช่องว่างที่ติดกันเป็นช่องใหญ่หนึ่งช่อง (ถูก แต่ถ้าช่องว่างไม่ได้ติดกันก็ช่วยไม่ทันการ)
  • Compaction — ลาก process ทั้งหมดมาอัดติดกันทางซ้าย รวมของว่างไว้ปลายเดียว — ได้ที่ว่างใหญ่จริง แต่overhead แพงมาก ต้องหยุดงาน ย้ายข้อมูล คำนวณตำแหน่งใหม่ และทำได้เฉพาะเมื่อ relocation เป็นแบบ dynamic (ทำตอน execution time)
🎯 สูตรลับแยกสอง fragmentation (ข้อถูก/ผิดออกวนไป)

Fixed Partition = Internal (เศษอยู่ในช่องจองแล้ว) · Variable Partition และ Segmentation = External (เศษกระจายนอก) · Paging = ไม่มี External แต่มี Internal ที่เพจสุดท้าย (บทถัดไป)

5. First-fit · Best-fit · Worst-fit 🔥

เมื่องานขนาด S มาขอ จะเลือกหลุม (hole) ไหนดี? — ตัวอย่างวิดีโอ: หลุมเรียงตามลำดับใน RAM: 16 MB, 14 MB, 5 MB, 30 MB และมี process ใหม่ต้องการ 13 MB:

First-fit — เจอช่องแรกที่พอ จบเกม

ไล่จากซ้าย: 16 ≥ 13 ✓ → ลงช่อง 16 MB ทันที เหลือทิ้ง 3 MB · จุดเด่น: เร็วที่สุด (ไม่ต้องสแกนครบ) จุดด้อย: ใช้พื้นที่เปลืองกว่า

13MB ลงนี่ (First-fit) เหลือ 3 14 5 30

Best-fit — สแกนครบ เลือกช่องที่ "ใหญ่พอ + แน่นที่สุด"

16 → เหลือ 3 · 14 → เหลือ 1 · 5 → ไม่พอ · 30 → เหลือ 17 → เลือก 14 MB เหลือทิ้ง 1 MB · จุดเด่น: คุ้มสุด จุดด้อย: ช้า (สแกนครบทุกช่อง) และมักทิ้งเศษจิ๋ว ๆ ใช้ต่อไม่ได้

16 13MB ลงนี่ (Best-fit) เหลือ 1 5 30

Worst-fit — สแกนครบ เลือกช่องใหญ่ที่สุด

ใหญ่สุดคือ 30 MB → ลงที่นั่น เหลือทิ้ง 17 MB · แนวคิด: ทิ้งเศษชิ้นใหญ่ไว้ให้งานถัดไปใช้ต่อได้ (แต่โดยรวมมักแพ้ best-fit)

16 14 5 13MB ลงนี่ (Worst-fit) เหลือ 17
💡 วิธีทำในห้องสอบ (เร็ว 30 วินาที)

1) เขียนเลขหลุมเรียงตามลำดับที่โจทย์ให้มา (ห้ามจัดเรียงเอง!) 2) First-fit = วิ่งจากซ้ายหยุดหลุมแรกที่ ≥ S 3) Best-fit = เทียบ (หลุม − S) ทุกหลุมที่ ≥ S เลือกค่าน้อยสุด 4) Worst-fit = เลือกหลุมใหญ่สุด · อย่าลืมเขียน "เศษเหลือ" ทิ้งไว้ให้ข้อถัดไปด้วยถ้าโจทย์ให้จัดหลายงานต่อกัน

6. Segmentation — แบ่งตามสายตาโปรแกรมเมอร์ 🔥

Paging แบ่งตามใจฮาร์ดแวร์ (ก้อนเท่ากัน) แต่ Segmentation แบ่งตามมุมมองของคนเขียนโปรแกรม: main, function, object, stack, global variables — แต่ละ segment ขนาดไม่เท่ากัน (เป็น logical unit)

  • Logical address = คู่ลำดับ <segment-number (s), offset (d)>
    • บ
  • Segment table แต่ละแถวมี Base (ตำแหน่งเริ่มใน RAM) + Limit (ความยาว segment)
  • Register ประกอบ: STBR ชี้ตำแหน่งตาราง · STLR บอกจำนวน segment — s ถูกต้องถ้า s < STLR
ขั้นแรก: เช็ค d < Limit — ถ้า d ≥ Limit → TRAP (Segmentation Fault!)
ขั้นต่อมา: Physical Address = Base + Offsetเช็คขอบเขต "ก่อนเสมอ" แล้วค่อยบวก — เคร่งครัดเรื่อง < ไม่ใช่ ≤

🎯 ข้อสังเกตปิดบท

Segmentation สวยตามใจคน แต่ segment แต่ละตัวต้องวางใน RAM "ต่อเนื่องเป็นผืนเดียว" ดังนั้นยังเจ็บปวดกับ External Fragmentation เหมือน variable partition — แก้สุดท้ายด้วยการรวมพลังกับ paging เป็น segmentation/paging (v = (s, p, d)) ตามที่มีใน handout
