บทที่ 2 — OS Structure และการเรียกใช้บริการผ่าน System Call

บทนี้ตอบคำถามว่า "โปรแกรมของเราคุยกับ OS ยังไง?" — คำตอบคือ System Call และโครงสร้างเคอร์เนลกำหนดว่า OS นั้นจัดวางงานยังไง ข้อสอบมักถามถึงชนิดของ system call และจุดต่าง Monolithic vs Microkernel

1. OS ให้บริการอะไรบ้าง (Operating System Services)

มอง OS เป็น "ร้านค้าบริการ" ที่มีเคาน์เตอร์ให้บริการ 9 ด้าน — จำพววหมวดก็พอ ออกถูก/ผิดเยอะ:

บริการทำอะไรตัวอย่าง
User Interfaceช่องทางให้คนคุยกับเครื่องCLI, GUI, Batch
Program executionโหลดโปรแกรมเข้า memory รัน และจบการทำงาน (ปกติหรือผิดปกติ)ดับเบิลคลิก .exe
I/O operationsโปรแกรมร้องขออ่าน/เขียนไฟล์หรืออุปกรณ์ I/O — OS ทำให้แทนprintf, อ่านกล้อง
File-system manipulationสร้าง/ลบ/ค้นหาไฟล์-directory, จัดการสิทธิ์mkdir, chmod
Communicationsprocess คุยกัน (เครื่องเดียวหรือข้ามเครือข่าย) ผ่าน shared memory หรือ message passingpipe, socket — เชื่อมบท 6!
Error detectionจับตา error ของ hardware/software ตลอด แล้วจัดการให้เหมาะสมCPU พัง, RAM error
Resource allocationแบ่งทรัพยากร (CPU, memory, อุปกรณ์) ให้หลาย process พร้อมกันแบ่ง CPU time
Accountingจดบันทึกว่าใครใช้ทรัพยากรเท่าไร ชนิดไหน (เก็บสถิติ/เก็บเงิน)usage stat
Protection & Securityควบคุมการเข้าถึงทรัพยากร (protection) + ยืนยันตัวตนกันคนนอก (security)permission, login

2. User Interface — CLI, GUI, Batch

  • CLI (Command Line Interface) / command interpreter — พิมพ์คำสั่งตรง ๆ เช่น bash, cmd ข้อดีคือเร็วและสั่งอะไรก็ได้ละเอียด
    • ใช้งานได้ 2 แบบ: ฝังอยู่ใน kernel เลย หรือ เป็นโปรแกรมภายนอก (มีหลาย flavor เช่น bash, zsh — shell แต่ละตัวทำงานเหมือนกันแต่หน้าตา/ฟีเจอร์ต่าง)
    • หน้าที่หลักของ shell: ดึงคำสั่งจากผู้ใช้ → สั่งการทำงาน บางคำสั่งเป็น built-in บางคำสั่งคือชื่อโปรแกรม (จำไว้ — ประเด็น cd เป็น built-in จะโผล่อีกทีในเรื่อง exec())
  • GUI (Graphics User Interface) — หน้าต่าง ไอคอน เมาส์ ใช้ง่ายกับคนทั่วไป
  • Batch — คำสั่งอยู่ในไฟล์ รันรวดเดียว ไม่ต้องคนคุม

3. System Call — ประตูบริการของ OS 🔥

System Call = API ที่ให้โปรแกรมเข้าถึงฟังก์ชัน/บริการของ OS โดยทั่วไปเขียนด้วยภาษาระดับสูง (C/C++) — เมื่อโปรแกรมต้องการสั่งงานฮาร์ดแวร์มันไม่ได้สั่งตรง แต่ "ยื่นเรื่อง" ผ่าน system call

🏦 เปรียบเทียบ

System call = เคาน์เตอร์ธนาคาร คุณ (โปรแกรม user) เข้าห้องหลัง (kernel) เองไม่ได้ ต้องยื่นแบบฟอร์ม (system call) ให้พนักงาน (OS) ทำให้แทน จบแล้วรับผลลัพธ์กลับ

โปรแกรมใช้ API แทน system call ตรง ๆ ทำไม?

จริง ๆ แล้วโปรแกรมเมอร์เรียกผ่าน API ระดับสูง ไม่ได้เรียก system call ตรง ๆ เพราะ API มีข้อดี: โค้ดพกพาข้ามเครื่อง/OS ได้ (portability) และใช้ง่ายกว่า API ยอดนิยม 3 ตระกูล (ออกเติมคำ!):

Win32 API → Windows POSIX API → UNIX/Linux/macOS Java API → JVM

ตัวอย่างที่ต้องเข้าใจ: printf → write

printf("Hello");  // เราเรียกฟังก์ชันใน Standard C Library (API)
                // ข้างในมันเรียก system call write() เพื่อส่งข้อความออกหน้าจอจริง ๆ

4. ประเภทของ System Call

มี 6 กลุ่ม — ข้อสอบชอบยก system call มาให้จำแนกกลุ่ม:

กลุ่มใช้ทำอะไรตัวอย่างใน Windows / Unix
Process controlสร้าง/จบ process, โหลด-รันโปรแกรมCreateProcess, ExitProcess / fork(), exec(), exit(), wait()
File managementสร้าง/ลบ/เปิด/ปิด/อ่าน/เขียนไฟล์CreateFile, ReadFile / open(), read(), write(), close()
Device managementขอ-คืนอุปกรณ์, อ่าน/เขียนอุปกรณ์SetConsoleMode / ioctl(), read(), write()
Information maintenanceถาม/ตั้งข้อมูลเวลา วัน PID ฯลฯGetConsoleOutputCP / getpid(), time(), alarm()
Communicationsสร้างการคุยระหว่าง processCreatePipe, CreateFileMapping / pipe(), shmget(), kill()
Protectionควบคุมสิทธิ์การเข้าถึงSetFileSecurity / chmod(), chown()
🎯 โยงกับบทหลัง

สังเกตว่า fork/exec/exit/wait (บท 3) เป็น process control, pipe/shmget/kill (บท 6) เป็น communications — ข้อสอบเคยให้แยกว่า system call แต่ละตัวอยู่กลุ่มไหน

5. สถาปัตยกรรมของเคอร์เนล (Kernel Architectures)

5.1 Monolithic Kernel (เคอร์เนลก้อนเดียว)

รวมทุกบริการไว้ใน kernel ก้อนใหญ่ก้อนเดียว — filesystem, driver, networking, memory management อยู่รวมกันใน kernel mode หมด

  • ✅ เร็ว — เรียกบริการไหนก็อยู่ในก้อนเดียวกัน ไม่ต้องส่งข้อความข้ามชั้น
  • ❌ ใหญ่ ซับซ้อน บำรุงรักษายาก — driver ตัวเดียวพังอาจลากทั้งระบบลง (ระบบ crash ทั้งเครื่อง)
  • ตัวอย่าง: Linux แบบดั้งเดิม, UNIX ยุคแรก

5.2 Microkernel (เคอร์เนลจิ๋ว)

เหลือใน kernel เฉพาะสิ่งจำเป็นที่สุด (IPC, การจัดคิว CPU, memory พื้นฐาน) — ส่วนอื่นทั้งหลาย (filesystem, driver, network) ถีบออกไปรันเป็น user-space server processes คุยกันผ่าน message passing

  • ✅ เสถียร — service พังก็รีสตาร์ท service นั้น เครื่องไม่ลง, เพิ่ม/ถอดบริการง่าย, ปลอดภัย (kernel เล็ก ตรวจง่าย)
  • ❌ ช้ากว่า — เพราะทุกบริการต้องส่ง message ข้ามขอบเขต user/kernel (overhead ของ IPC)
  • ตัวอย่าง: Mach, QNX, MINIX
🏢 เปรียบเทียบ

Monolithic = บริษัทที่ทุกแผนกอยู่ชั้นเดียวกัน คุยกันเร็วมาก แต่ถ้าไฟไหม้ห้องนึง ทั้งชั้นลุก · Microkernel = แต่ละแผนกอยู่ตึกแยก คุยกันทางโทรศัพท์ (ช้าหน่อย) แต่ตึกไหนไหม้ก็แค่สร้างตึกนั้นใหม่ ส่วนอื่นทำงานต่อ
