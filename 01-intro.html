1. OS คืออะไร — เริ่มจากภาพใหญ่ก่อน

ลองนึกภาพร้านอาหารที่มีลูกค้า (โปรแกรมของเรา) เข้ามาสั่งอาหารทุกชนิด แต่ในครัวมีเตาแค่เตาเดียว น้ำแค่ก๊อกเดียว พ่อครัวแค่คนเดียว — ใครจะเป็นคนจัดคิว แบ่งเตา บอกว่าใครได้ใช้อะไรก่อน-หลัง ใช้เท่าไร? คนที่ทำหน้าที่นั้นคือ "หัวหน้าร้าน" นั่นเอง

Operating System (OS) ก็คือหัวหน้าร้านของคอมพิวเตอร์ — เป็นซอฟต์แวร์ที่ทำหน้าที่ จัดการทรัพยากรทั้งหมดของเครื่อง (CPU, หน่วยความจำ, อุปกรณ์ I/O, ไฟล์) และ ควบคุมว่าใครใช้ทรัพยากรไหน อย่างไร และเท่าไร

เป้าหมายหลักของ OS มี 3 ข้อ (จำไว้ ออกถูก/ผิดได้):

  • Run user programs — ทำให้โปรแกรมของผู้ใช้รันได้ และทำให้ผู้ใช้แก้ปัญหาได้ง่ายขึ้น (user-friendly)
  • Optimize hardware utilization — ใช้ฮาร์ดแวร์ให้คุ้มค่าที่สุด ไม่ปล่อยให้ CPU นั่งเบื่อ
  • เป็นตัวกลางระหว่างผู้ใช้กับฮาร์ดแวร์

2. Kernel vs System Programs vs Application Programs

เวลาพูดถึง "OS" แบบแคบ ๆ เราหมายถึง Kernel เท่านั้น — ส่วนที่ทำงานพื้นฐานจริง ๆ ของ OS (ส่วนที่เหลือแบ่งเป็น 2 พวก):

ชั้นคืออะไรตัวอย่าง
Kernelหัวใจของ OS ทำหน้าที่พื้นฐานทั้งหมด รันในโหมดพิเศษ (kernel mode)ตัวจัดคิว CPU, ตัวจัดการหน่วยความจำ
System Programsโปรแกรมที่มากับ OS เพื่ออำนวยความสะดวกshell (bash), file manager, compiler
Application Programsโปรแกรมที่ผู้ใช้ติดตั้งเองเกม, Chrome, Excel
🍽️ เปรียบเทียบ

Kernel = พ่อครัวในครัวหลัง (แตะของได้ทุกอย่าง) · System Program = พนักงานเสิร์ฟ (ตัวกลางรับออเดอร์) · Application = ลูกค้า (ขอบริการเท่านั้น ห้ามล้วงเข้าครัว!)

3. องค์ประกอบ (Components) ของ OS

OS แบ่งงานกันทำเป็น Manager หลายตัว แต่ละตัวต้องทำ 3 อย่างเหมือนกัน: Monitor ทรัพยากรของตัวเอง, ทำตามกฎ "ใครได้อะไร เมื่อไร เท่าไร", Allocate ให้ตอนถึงคิว และ Deallocate คืนเมื่อใช้เสร็จ

Memory Manager Processor Manager Device Manager File Manager Network Manager Security Manager User Command Interface

💡 Processor Manager คือตัวเดียวกับที่ทำเรื่อง Process และ CPU Scheduling ในบทที่ 3–5 · Memory Manager คือพระเอกของบท 10–12

4. ขั้นตอนการบูตเครื่อง (Boot Process) 🔥

Booting = การสตาร์ทคอมโดยการโหลด Kernel เข้าหน่วยความจำ ลำดับขั้นตอนเป็นข้อสอบโปรด เพราะเติมตัวเลขลำดับได้ มาไล่ทีละขั้น:

  1. Power On — กดปุ่มเปิดเครื่องไฟฟ้าวิ่งเข้าชิ้นส่วน CPU เริ่มรันคำสั่งแรกจาก BIOS (หรือ UEFI) ซึ่งเก็บอยู่ในชิปบนเมนบอร์ด
  2. POST (Power-On Self-Test)BIOS/UEFI ตรวจฮาร์ดแวร์ว่าพร้อมไหม — เช็ค RAM, CPU, ดิสก์, อุปกรณ์ต่อพ่วง (ถ้าพังจะบี๊บร้องไห้ใส่เรา)
  3. Boot Loader Selection
    • BIOS → ไปหา MBR (Master Boot Record) บนดิสก์ boot drive — ในนั้นมีข้อมูล partition และ bootloader
    • UEFI → ไปหา ESP (EFI System Partition) — พาร์ติชันพิเศษที่เก็บ bootloader + driver แล้วอ่าน BCD (Boot Configuration Data) เพื่อเลือก bootloader เริ่มต้น
  4. Bootloader ExecutionBIOS โหลดและรัน bootloader จาก MBR / UEFI โหลดจาก ESP
  5. OS Loadbootloader หาและโหลด OS Kernel เข้า RAM
  6. OS InitializationOS ทำหน้าที่ต่อจนจบ — เริ่มบริการต่าง ๆ แล้วส่งมอบเครื่องให้ผู้ใช้ใช้งาน
ประเด็นBIOS (เก่า)UEFI (ใหม่)
โหมดรัน16-bit real mode32/64-bit — เร็วกว่า, ใช้ RAM ใหญ่ได้
ตารางพาร์ติชันMBR — จำกัดขนาด/จำนวนพาร์ติชันGPT — ยืดหยุ่น รองรับดิสก์ใหญ่
ที่เก็บ bootloaderMBRESP
Secure Bootไม่มีมี — เช็คลายเซ็นดิจิทัลของ bootloader กันมัลแวร์
ความเร็วบูตช้ากว่าเร็วกว่า (เข้าถึง bootloader โดยตรง)
🎯 จุดหลอกข้อสอบ

• BIOS คู่กับ MBR, UEFI คู่กับ ESP + GPT — อย่าสลับ!
• POST เกิดก่อนหา bootloader เสมอ
• Booting นิยาม = "starting a computer by loading the kernel"

5. Dual Mode Operation 🔥

ถ้าทุกโปรแกรมแตะฮาร์ดแวร์ได้ตรง ๆ โปรแกรมดี ๆ ตัวหนึ่งเขียนพลาดหรือไวรัสตัวหนึ่งสั่งลบดิสก์ทั้งลูกได้เลย OS จึงมี "ประตูรั้ว" 2 โหมด โดยใช้ฮาร์ดแวร์ช่วยเฝ้า:

  • Mode Bit — บิตพิเศษที่ฮาร์ดแวร์เก็บไว้บอกว่าตอนนี้เครื่องกำลังรันอะไร:
    • 0 = Kernel mode (monitor mode / supervisor mode) — ทำอะไรก็ได้ ใช้คำสั่งพิเศษ (privileged instructions) ได้
    • 1 = User mode — ทำได้แค่งานทั่วไป ห้ามแตะของสำคัญ
  • Privileged instructions — คำสั่งอันตราย (เช่น เปิด/ปิด interrupt, เขียน I/O ตรง) ใช้ได้เฉพาะ kernel mode
  • เมื่อเกิด interrupt หรือ fault ฮาร์ดแวร์จะสลับไป kernel mode อัตโนมัติ
🏦 เปรียบเทียบ

User mode = ลูกค้ายืนหน้าเคาน์เตอร์ธนาคาร (เข้าถึงได้แค่โซนลูกค้า) · System call = การยื่นบัตรคิวขอบริการ · Kernel mode = พนักงานเดินเข้าห้องหลังเข้าถึงตู้เซฟได้ แต่ทำเฉพาะตามที่ลูกค้าขอเท่านั้น

6. OS กับฮาร์ดแวร์ทำงานร่วมกันผ่าน Interrupt

จุดสำคัญ: OS เป็น "interrupt driven" — ไม่มีงานก็นั่งเฉย ๆ รอให้มีเหตุการณ์มาเรียก ไม่ใช่นั่งถามหางานทุกวินาที (นั่นทำให้ CPU ทำงานอย่างอื่นไปพลางได้)

  • I/O devices กับ CPU ทำงานพร้อมกันได้ (concurrently) — แต่ละอุปกรณ์มี device controller ดูแลของตัวเอง
  • เมื่ออุปกรณ์ทำงานเสร็จ controller จะ ยิง interrupt บอก CPU ว่า "เสร็จแล้วนะ"
  • เกิด interrupt → ฮาร์ดแวร์เซฟตำแหน่งคำสั่งที่กำลังรันค้างไว้ → ไปรันที่ Interrupt Service Routine (ISR) ตามที่อยู่ใน Interrupt Vector (ตารางเก็บที่อยู่ของ ISR ทุกชนิด)
⚠️ Trap ต่างจาก Interrupt ยังไง (ออกถูก/ผิดบ่อย!)

Interrupt = มาจากฮาร์ดแวร์ (อุปกรณ์เรียก) · Trap = interrupt ที่มาจากซอฟต์แวร์ — เกิดได้ 2 กรณี: โปรแกรม error (exception เช่น หารศูนย์) หรือโปรแกรมขอบริการ OS ผ่าน system call สองอย่างนี้เข้า kernel mode เหมือนกัน แต่ต้นทางต่างกัน

7. Virtual Machine (VM) คืออะไร

VM = จำลอง "เครื่องคอมพิวเตอร์ทั้งเครื่อง" เป็นซอฟต์แวร์ แล้วติดตั้ง OS เต็มตัวลงไปในเครื่องจำลองนั้นได้อีกที (เช่น เครื่อง Windows จริง รัน Ubuntu จำลองอยู่ข้างใน) ทำให้ 1 เครื่องจริง มีได้หลาย "เครื่องเสมือน" ที่แยกกันสนิท

ของที่ใช้กันบ่อย: VMware, VirtualBox, และ JVM (Java Virtual Machine) ที่ทุกคนในสายคอมเจอแน่นอน — JVM จำลองเครื่องสำหรับ "รัน bytecode ของ Java" โดยเฉพาะ

ข้อดี: แยกฉนวน (isolation) ปลอดภัย ทดลองอะไรก็ได้ไม่พังเครื่องจริง · ข้อเสีย: หนัก เพราะต้องจำลองทั้งเครื่อง + OS เต็มตัว

8. Container & Docker

ปัญหาคลาสสิกของโปรแกรมเมอร์: "ในเครื่องผมรันได้นะ!" (It works on my machine) และ Dependency hell (ติดตั้งไลบรารีสู้กันจนเครื่องพัง) — Container ถือกำเนิดมาแก้สองปัญหานี้

Container = การห่อโปรแกรม + ทุก dependency ที่ต้องใช้ ใส่กล่องเดียวมาตรฐานเดียว แล้วกล่องนี้จะรันเหมือนกันทุกเครื่อง เพราะมันแชร์ kernel ของ OS แม่แทนที่จะจำลอง OS ใหม่ทั้งตัว

9. ประเภทของ OS

แบ่งได้ 4 มุม ข้อสอบชอบให้จับคู่ตัวอย่างกับประเภท:

9.1 ตามวิธีป้อนข้อมูล (How data is entered)

  • Batch System — งานถูกเข้าคิวแล้วรันต่อเนื่องเป็นชุด ๆ ไม่มีคนแทรกแซง (จุดเริ่ม OS ยุคแรก) มี 2 แบบ:
    • Single-programmed batch — รันทีละงาน งานเสร็จค่อยงานใหม่ (CPU ว่างตอนรอ I/O เปล่า ๆ)
    • Multi-programmed batch — มีหลายงานอยู่ใน RAM พร้อมกัน งานนึงรอ I/O สลับไปรันงานอื่นเลย (CPU ไม่ว่างเปล่า) — บรรพบุรุษของ multiprogramming ที่โผล่อีกทีในบท memory
  • Interactive System — ผู้ใช้คุยกับเครื่องสด ๆ ต้องมี time-sharing (แบ่งเวลา CPU ให้หลายงาน) เกิดมาเพราะโปรแกรมเมอร์อยากแก้ bug ไว ๆ ไม่ต้องรอคิว batch
  • Hybrid System — ผสมทั้ง batch (รันเบื้องหลังตอนเครื่องว่าง) และ interactive

9.2 ตามจำนวนผู้ใช้/งานที่รองรับ

แบบตัวอย่าง
Single-user, single-taskingMS-DOS
Single-user, multi-taskingOS บนเดสก์ท็อป/แล็ปท็อป (Windows, macOS)
Multi-user, multi-taskingOS ฝั่ง Server (Linux Server, Windows Server)

9.3 ระบบวัตถุประสงค์เฉพาะ (Special Purpose)

  • Real-Time System — ต้องตอบสนองภายในเวลาที่กำหนด
    • Hard real-time — พลาด deadline = ความพังทลาย ไม่มีดิสก์ (เก็บข้อมูลใน RAM/ROM เท่านั้น) ใช้ time-sharing ไม่ได้ เช่น VxWorks, RTXC (ระบบควบคุมเครื่องบิน, เบรก ABS)
    • Soft real-time — ช้าไปหน่อยยังรับได้ แค่คุณภาพลด เช่น มัลติมีเดีย, VR
  • Embedded System — คอมเฉพาะทางฝังในเครื่องใหญ่ ทำงานเฉพาะอย่าง ทรัพยากรจำกัด (เครื่องซักผ้า, รถยนต์, IoT)

9.4 ตามสถาปัตยกรรมคอมพิวเตอร์

  • Single Processor — CPU ตัวเดียว
  • Parallel Systems (Multiprocessor, tightly-coupled) — หลาย CPU อยู่ในเครื่องเดียวกัน เช่น dual-core แชร์ bus/-clock/หน่วยความจำ
  • Distributed Systems (loosely-coupled) — หลายเครื่องแยกกัน คุยกันผ่าน network แต่ละเครื่องมี resource ตัวเอง
    • Network OS — แต่ละเครื่องมี OS ตัวเอง แค่เปิดบริการแชร์ผ่านเน็ต เช่น Windows Server, Ubuntu Server
    • Distributed OS — หลายเครื่องถูก OS เดียวจัดการเหมือนเป็นเครื่องเดียว เช่น Sprite, Amoeba
🎯 จุดหลอกข้อสอบ

• Parallel = tightly-coupled / Distributed = loosely-coupled — จับคู่คำพวกนี้บ่อยมาก
• Hard real-time เข้ากันไม่ได้กับ time-sharing
• MS-DOS คือ single-user single-tasking / JVM คือ single-process multi-threaded (เชื่อมบท Thread)
