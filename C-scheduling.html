C. CPU Scheduling — Gantt · TAT · WT (OSNo04 สไลด์ท้าย + วิดีโอ 6.x)

📖 รู้จักส่วนนี้ก่อนอ่าน

ความหมาย: CPU Scheduling = การตัดสินใจว่า process ไหนจะได้ใช้ CPU "ตัวต่อไป" เมื่อหลายงานแย่งกัน — มีหลายอัลกอริทึม เช่น FCFS (มาก่อนได้ก่อน), SJF (งานสั้นก่อน), RR (วนแบ่งเวลา)

ความสำคัญกับข้อสอบ: โจทย์วาด Gantt (แผนภูมิช่วงเวลา) หา TAT/WT เป็นข้อคำนวณหลักประจำทุกปี — ฝึกให้ทำข้อละไม่เกิน 2 นาที ใช้เทคนิค "หา TAT ก่อนแล้วลบ BT เสมอ"

ใช้จริงในคอมพิวเตอร์: Windows/Linux/macOS ใช้แนวคิด priority + time slice (โควตาเวลาแบบ RR) จริง ๆ ในตัวจัดคิวของเคอร์เนล — เปิด Task Manager เห็น process แย่ง CPU ด้วยกลไกพวกนี้ทั้งหมด

C1. พื้นฐาน + สูตรทุกตัวที่ใช้คิดเลข

  • CPU Scheduler (ตัวจัดคิว CPU) เลือก process จาก ready queue ให้ใช้ CPU · Non-preemptive = รันจนจบ/ขอออกเอง · Preemptive (ขัดจังหวะ/แย่งได้) = ขัดกลางคันได้ (หมดเวลา/มีตัวสำคัญกว่ามา)
  • CPU burst = ช่วงที่ process ใช้ CPU ติดกัน · I/O-bound = burst สั้นถี่ / CPU-bound = burst ยาว
Turnaround Time (เวลารวมในระบบ): TAT = Completion − Arrivalเวลารวมตั้งแต่งานมาถึง → เสร็จ
Waiting Time (เวลารอคิว): WT = TAT − Burst Time (เวลาที่ต้องใช้ CPU)🟢 เทคนิคทำเร็ว: หา TAT ก่อนแล้วลบ BT เสมอ — โดยเฉพาะ preemptive ที่งานโดนแทรกหลายรอบ
Response Time (เวลาตอบสนอง) = เวลาที่งานมาถึง → เริ่มได้ response ครั้งแรกเกณฑ์วัดอื่น: CPU utilization ↑, throughput ↑, TAT ↓, WT ↓, response ↓

C4. SRTF (งานที่เหลือสั้นสุดทำก่อน) — Shortest Remaining Time First (Preemptive SJF) 🔥

กติกา: งานใหม่มาถึง → เทียบ BT ของงานใหม่ กับ Remaining Time (เวลาที่เหลือ) ของงานที่รันอยู่ — งานใหม่สั้นกว่า = ขัดทันที

  1. 0–2: P1 รันไป 2 (เหลือ 5) — P2 มาถึง (BT=4) → เทียบ 4 < 5 → ขัด P1
  2. 2–4: P2 รันไป 2 (เหลือ 2) — P3 มาถึง (BT=1) → 1 < 2 → ขัด P2
  3. 4–5: P3 จบที่ 5 พอดี + P4 มาถึง (BT=4) → คิว: P1(5), P2(2), P4(4) → รัน P2 จบที่ 7
  4. 7: เหลือ P1(5), P4(4) → P4 จบที่ 11 → P1 เศษ 5 จบที่ 16

C5. Priority (ลำดับสิทธิ์) Scheduling (การจัดคิว)

  • CPU ให้งาน priority สูงสุดก่อน (มีทั้ง preemptive/non-preemptive) · SJF = priority ที่ใช้ "predicted next CPU burst" เป็น priority
  • ปัญหา Starvation (การอดตาย (ไม่ได้รันเลย)) (งานสิทธิต่ำไม่ได้รัน) → แก้ด้วย Aging: ยิ่งรอนานยิ่งเพิ่ม priority
  • ทิศทางตัวเลข: Unix-based → เลขน้อย = สิทธิสูง / Java Thread → เลขมาก = สูง (10 สูงสุด, default 5)

C7. Multilevel Queue (คิวหลายชั้น) & Multilevel Feedback Queue (MLFQ)

  • Multilevel Queue: แยก ready queue หลายคิว (เช่น foreground=RR / background=FCFS) — งานอยู่คิวไหนตลอดชีวิต ย้ายไม่ได้ · ระหว่างคิว: fixed priority (คิวหน้าจบก่อน — เสี่ยง starvation) หรือแบ่งเวลา (80/20)
  • MLFQ: งานย้ายคิวได้ → ทำ aging ได้ จัดกลุ่มตามพฤติกรรมได้

โมเดลตัวอย่าง (p.46–47): Q0 = RR q8ms → ไม่จบ ลง Q1 = RR q16ms → ยังไม่จบ ลง Q2 = FCFS จนจบ · คิวล่างได้รันเมื่อคิวบนว่างหมด
