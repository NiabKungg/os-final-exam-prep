1. File System รับผิดชอบอะไร

File system = องค์ประกอบสำคัญของ OS ที่จัดการข้อมูลบน storage (HDD, SSD, USB) โดยดึงความซับซ้อนระดับฮาร์ดแวร์ออกไป หน้าที่: ตั้งชื่อ+โครงสร้างไฟล์, เก็บข้อมูล, ดึง/แก้ไขข้อมูล, จัดการ metadata และ ความปลอดภัย/สิทธิ์การเข้าถึง

• Journaling = สมุดบันทึกการเปลี่ยนแปลง ทำให้ recover ไวหลังไฟดับ — NTFS/ext4/APFS มี, FAT32/exFAT ไม่มี

3. 3 วิธีจัดสรรพื้นที่ให้ไฟล์ 🔥

เล่นแบบเดียวกับบท memory แต่คราวนี้บนดิสก์ — จำเทียบกันได้เลย:

3.1 Contiguous Allocation — วางต่อกันเป็นผืนเดียว

  • Directory เก็บแค่ เริ่มบล็อกที่เท่าไร + ยาวกี่บล็อก (2 ค่าจบ)
  • ✅ เร็วมาก — อ่านเรียง ๆ ไม่ต้องเสียเวลา seek หัวอ่าน
  • ❌ External Fragmentation (เหมือน variable partition เป๊ะ!) + ขยายไฟล์ยาก — บล็อกถัดไปถูกจองก็ต้องย้ายไฟล์ทั้งก้อน

3.2 Linked Allocation — บล็อกกระจาย + ชี้ต่อกันเป็นสายโซ่

  • แต่ละบล็อกมี pointer ชี้บล็อกถัดไป — directory เก็บ start + end
  • ✅ ไม่มี external fragmentation · ขยายไฟล์ง่าย (ต่อสายโซ่ใหม่)
  • ❌ Random access ช้ามาก (อยากอ่านบล็อกที่ 100 ต้องไล่สายโซ่จาก 1) · บล็อกเสียพื้นที่ให้ pointer · pointer ตัวไหนพัง = ท่อนหลังของไฟล์หายหมด
  • ตัวช่วย: FAT (File Allocation Table) — ดึง pointer ทั้งหมดมารวมไว้ในตารางเดียว (อยู่ใน RAM) ทำให้ไล่โซ่ได้เร็วโดยไม่ต้องเปิดดิสก์ทีละบล็อก (นี่คือที่มาของชื่อ FAT filesystem!)

3.3 Indexed Allocation — รวม pointer ไว้ในบล็อกพิเศษ

  • ทุก pointer ของไฟล์รวมอยู่ใน Index Block — directory ชี้มาที่ index block จุดเดียว
  • ✅ Random access เร็ว (อ่าน index ครั้งเดียวรู้หมด) · ไม่มี external fragmentation
  • ❌ เปลืองบล็อกเก็บ index — ไฟล์เล็กแค่ไหนก็เสีย index block หนึ่งบล็อกเสมอ · ไฟล์ใหญ่มากต้องใช้ multi-level index
วิธีอ่านเรียง (sequential)สุ่ม (random access)Fragmentationขยายไฟล์
Contiguous🟢 เร็วสุด🟢 เร็วExternal ❌ยาก ❌
Linked🟡 ปานกลาง🔴 ช้ามากไม่ค่อยมีง่าย ✅

4. UNIX inode (Combined Scheme) — โจทย์คำนวณสำคัญ 🔥

UNIX ผสมทุกอย่างใน inode ที่มี pointer 15 ตัว:

Direct 12 ตัว → ชี้ data block ตรง ๆ Single indirect 1 ตัว Double indirect 1 ตัว Triple indirect 1 ตัว

ตัวอย่างจากวิดีโอ (block size 4 KB, pointer 4 bytes):

  1. หาจำนวน pointer ต่อ 1 index block4 KB ÷ 4 bytes = 1024 ช่อง (ตัวเลขทองที่ต้องหาก่อนเสมอ)
  2. Direct 12 ตัว12 × 4 KB = 48 KB — ไฟล์เล็กเข้าถึงได้เร็วสุดไม่ต้องผ่าน index
  3. Single indirect1024 × 4 KB = 4 MB
  4. Double indirect1024 × 1024 × 4 KB = 4 GB
  5. Triple indirect1024³ × 4 KB = 4 TB
ขนาดไฟล์สูงสุด ≈ 48 KB + 4 MB + 4 GB + 4 TB ≈ 4 TBข้อผิดพลาดยอดฮิต: ลืมบวก direct 48 KB หรือ ลืมหา "1024 ช่องต่อบล็อก" ก่อน

💡 handout ยังมีตัวอย่าง two-level index ของระบบ block 512 bytes: สูงสุด 512³ bytes — หลักคิดเหมือนกัน: entries ต่อบล็อก × ขนาดบล็อก ยกกำลังชั้น

5. Directory และ Link

Directory = ตารางแปลง "ชื่อไฟล์ → ข้อมูลไฟล์" (symbol table) มี operation: ค้นหา, สร้าง, ลบ, ลิสต์, เปลี่ยนชื่อ, เดินทางท่องระบบ

  • Tree structure — ไฟล์มี parent เดียว ปลอดภัยแต่แชร์ไฟล์ไม่ได้
  • Acyclic graph — ไม่มีวงวน แต่ยอมให้แชร์ (มีหลาย parent) ผ่าน link — ยืดหยุ่นแต่ปวดหัวเรื่อง: ไฟล์เดียวมีหลายชื่อ (aliasing) และถ้าลบแล้วใครเสียใคร

Hard Link vs Symbolic (Soft) Link — คู่ที่ออกทุกปี 🔥

Hard Link ln original newSymbolic Link ln -s original new
ชี้ไปที่inode เดียวกันโดยตรง + เพิ่ม reference countสร้างไฟล์ใหม่ที่เก็บ"path" ของต้นทาง (shortcut)
ลบต้นฉบับแล้ว✅ ข้อมูลยังอยู่ — ตายเมื่อ reference count = 0 (ลบ link ทุกตัว)❌ กลายเป็น broken/dangling link (ชี้หาอะไรที่ไม่มีแล้ว)
ข้าม partition/file system❌ ห้าม✅ ได้
ทำกับ directory❌ ห้าม (ส่วนใหญ่ เพื่อกัน cycle)✅ ได้
🏠 เปรียบเทียบ

Hard link = ลงทะเบียนบ้านเพิ่มอีกชื่อ — บ้านหลังเดิม อยู่ต่อจนคนทะเบียนหมด · Symbolic link = กระดาษโน้ตเขียนว่า "บ้านอยู่ซอย 5" — โยนบ้านทิ้งกระดาษก็ชี้อากาศ (dangling)

💡 ปัญหาการลบไฟล์แชร์ใน acyclic graph มี 2 แนวทาง: ลบเมื่อใดก็ได้ (เสี่ยง dangling pointer) หรือ เก็บ reference count ลบจริงเมื่อนับ = 0 (แนวทาง hard link) — และต้องระวังตรวจ cycle (แก้ง่าย ๆ คือ bypass ทาง link ตอนท่องระบบ)

6. Mounting

  • Mounting = ติดระบบไฟล์จากอุปกรณ์ (พาร์ติชัน, USB, network fs) เข้ากับ directory tree ของระบบ ณ mount point (เช่น /mnt/usb)
  • คำสั่ง: mount /dev/sdb1 /mnt/usb · ก่อนถอดอุปกรณ์ต้อง umount /mnt/usb เพื่อให้การเขียนค้าง ๆ เสร็จสมบูรณ์ (ไม่งั้นข้อมูลพัง!)

7. สิทธิ์ RWX ↔ ตัวเลขฐานแปด 🔥

สิทธิ์แบ่ง 3 กลุ่ม: Owner / Group / Others — กลุ่มละ 3 บิต (r w x) ค่าบิต = กำลังสอง:

R = 2² = 4 W = 2¹ = 2 X = 2⁰ = 1

ตัวอย่างจาก handout: 761

  1. Owner = 74+2+1 = rwx — อ่าน/เขียน/รัน ครบ
  2. Group = 64+2+0 = rw- — อ่าน+เขียนได้ รันไม่ได้
  3. Others = 10+0+1 = --x — รันได้อย่างเดียว

ตั้งค่าด้วย chmod 761 filename — ข้อผิดพลาดที่มักเจอ: ตี 6 เป็น r-x (จริง ๆ r-x = 4+1 = 5)

💡 เทคนิคแปลงเร็ว

7 = ทุกอย่าง (rwx) · 6 = rw- · 5 = r-x · 4 = r-- · 0 = --- (ไม่มีสิทธิ์) — เจอเลขไหนให้บวก 4/2/1 กลับ เจอตัวอักษรให้รวมค่าเป็นเลขกลับ ทำได้ 5 วินาที
