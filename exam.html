A2Synchronizationถูก/ผิด · +2 / −1 / 0
การเรียก x.signal() บน condition variable ของ monitor เมื่อไม่มี process รออยู่ จะถูกเก็บค่าไว้ใช้ปลุก process ถัดไปที่มารอภายหลัง
กถูก

A3Deadlockถูก/ผิด · +2 / −1 / 0
หาก Resource-Allocation Graph ไม่มี cycle เลย ระบบรับประกันได้ว่าไม่เกิด deadlock
กถูก
ขผิด
เฉลย: ถูกไม่มี cycle = ไม่มีวงจรรอ = ไม่มี deadlock แน่นอน 100% (ส่วนมี cycle จะรับประกันได้เฉพาะเมื่อทรัพยากรชิ้นเดียวต่อประเภท)
A4IPCถูก/ผิด · +2 / −1 / 0
หลังจาก pipe(pfd) แล้วตามด้วย fork() และให้ parent เป็นผู้ส่ง — parent ควรปิด pfd[0] และ child ควรปิด pfd[1]
กถูก
ขผิด
เฉลย: ถูกparent = ผู้ส่ง เก็บปลายเขียน pfd[1] ปิดปลายอ่าน pfd[0] · child = ผู้รับ เก็บ pfd[0] ปิด pfd[1] — ปิดให้ครบท่อจึงกลายเป็นทางเดียวที่ทำงานแน่นอน
A5Virtual Memoryถูก/ผิด · +2 / −1 / 0

ขผิด
เฉลย: ผิดFIFO มี Belady's Anomaly — string 1,2,3,4,1,2,5,1,2,3,4,5 กับ 3 frames เกิด 9 faults แต่ 4 frames เกิด 10 faults (เพิ่ม frame แล้ว fault โตขึ้น!)
A6File Systemถูก/ผิด · +2 / −1 / 0

ขผิด
เฉลย: ถูกsoft link เก็บแค่ "path" จึงข้าม partition/ชี้ directory ได้ แต่ต้นทางหาย = dangling ข้อความชุดนี้ถูกต้องครบ — ตรงข้ามกับ hard link ที่ห้ามทั้งสองอย่างแต่ทนการลบ

Part B — คำนวณ เติมตัวเลข

B1Paging 🔥เติมตัวเลข
Page size = 8 bytes · Page table: 0→2, 1→5, 2→3, 3→1 · Logical address = (p = 2, d = 3)
Physical address คือเท่าไร
เฉลย: 27เพจ 2 → frame 3 → PA = (3 × 8) + 3 = 24 + 3 = 27 — ขั้นตอน: เปิดตารางด้วย p → คูณ frame ด้วย page size → บวก offset
B2Paging — หาบิตเติมตัวเลข
ระบบมี logical address space ขนาด 2¹⁴ bytes และ page size = 2¹⁰ bytes — ฟิลด์ page number ต้องใช้กี่บิต
เฉลย: 10 บิตoffset ต้องใช้ 10 บิต (2¹⁰) → page number = 14 − 10 = 10 บิต → มีเพจได้ 2¹⁰ = 1,024 เพจ (ตรวจ: 1024 เพจ × 1KB = 1MB = 2¹⁴ ✓)
B3CPU Scheduling 🔥เติมตัวเลข
P1 (Arrival 0, BT 8), P2 (Arrival 1, BT 4), P3 (Arrival 2, BT 9), P4 (Arrival 3, BT 5) จัดด้วย SRTF — ไล่ได้ Gantt: P1(0–1), P2(1–5), P4(5–10), P1(10–13), P3(13–22)
ค่าเฉลี่ย Waiting Time คือเท่าไร (กรอกทศนิยมได้ เช่น 4.5)
เฉลย: 4.5ใช้ WT = TAT − BT: P1: TAT=13−0=13, WT=13−8=5 · P2: TAT=5−1=4, WT=4−4=0 · P3: TAT=22−2=20, WT=20−9=11 · P4: TAT=10−3=7, WT=7−5=2 → รวม 5+0+11+2 = 18 ÷ 4 = 4.5 (เทคนิคอาจารย์ใช้ได้เป๊ะ ไม่ต้องไล่ช่วงรอจาก Gantt เลย)
B4Page Replacement 🔥เติมตัวเลข
Reference string: 2, 3, 2, 1, 5, 2, 4, 5, 3, 2, 5, 2 · RAM มี 3 frames เริ่มว่าง · ใช้ LRU
เกิด page fault รวมกี่ครั้ง
เฉลย: 6 ครั้งไล่ LRU (แทนตัวที่ไม่ได้ใช้นานสุด): 2F → 3F → 2H → 1F (frames 2,3,1) → 5F แทน 3 (LRU คือ 3 เพราะ 2 เพิ่งถูกใช้) → 2H → 4F แทน 1 → 5H → 3F แทน 4 → 2H → 5H → 2H รวม F ที่ตำแหน่ง 1, 2, 4, 5, 7, 9 = 6 ครั้ง · เทคนิค: เขียนเลขกำกับ "ใช้ล่าสุดตอนไหน" ใต้แต่ละ frame จะไม่งง
B5TLB / EATเติมตัวเลข
TLB search = 0.2 μs, hit ratio = 60%, memory access = 1 μs — EAT = กี่ μs
เฉลย: 1.6 μsHit (0.6): 0.2+1 = 1.2 · Miss (0.4): 0.2+1+1 = 2.2 → EAT = 0.6×1.2 + 0.4×2.2 = 0.72 + 0.88 = 1.6 μs (สูตรลัด 2+ε−α = 2+0.2−0.6 = 1.6 ✓ ตรงกัน)
B6First-fit / Best-fitเติมตัวเลข
หลุมว่างเรียงตามลำดับ: 100 KB, 500 KB, 200 KB, 300 KB, 600 KB (แบบ handout) · มี process ต้องการ 212 KB
ถ้าใช้ Best-fit — process ลงหลุมขนาดเท่าไร (ตอบขนาดหลุม เป็น KB)
เฉลย: 300 KBหลุมที่พอ: 500 (เหลือ 288), 300 (เหลือ 88), 600 (เหลือ 388) — เหลือน้อยสุดคือ 300 → Best-fit เลือก 300 · (First-fit จะได้ 500, Worst-fit ได้ 600 — สามแบบต่างกันหมด!)
B7Segmentationเติมตัวเลข
Segment table: S1 (base 6300, limit 500), S2 (base 4300, limit 400)
Logical address <1, 200> physical address คือเท่าไร
เฉลย: 6500เช็ค: offset 200 < limit 500 ✓ → PA = base + d = 6300 + 200 = 6500 (จำลำดับ: เช็ค limit ก่อนเสมอ — ถ้า <2, 400> จะ trap เพราะ 400 ไม่ < 400)
B8Banker's Algorithmเติมตัวเลข
ตารางจาก handout: Available = (3,3,2) · Need: P0=(7,4,3), P1=(1,2,2), P2=(6,0,0), P3=(0,1,1), P4=(4,3,1) · Safe sequence <P1,P3,P4,P2,P0>
หลังจากรัน P4 เสร็จและคืนทรัพยากร (ตามลำดับข้างบน) ค่า Work ช่อง C จะเท่ากับเท่าไร
เฉลย: 5Work หลัง P1 = (5,3,2) · หลัง P3 = (7,4,3) · หลัง P4 = (7,4,3) + (0,0,2) = (7,4,5) → ช่อง C = 5 (ต่อไป P2 → (10,4,7), P0 → (10,5,7))

Part C — ไล่โค้ด

C1fork 🔥เติมตัวเลข
fork();              // จุดที่ 1
if (fork() == 0) {   // จุดที่ 2 — ทุกสายผ่าน
    fork();          // จุดที่ 3 — เฉพาะสายที่ได้ 0
}
fork();              // จุดที่ 4 — ทุกสายผ่าน
printf("hi\n");
มี process ทั้งหมดกี่ตัว (รวม process เริ่มต้น) — เคล็ดลับ: วาด process tree ทีละ fork จำไว้ว่าทุกสายที่ผ่าน fork จะทำให้จำนวนสาย "เป็นเท่าตัว"
เฉลย: 12 ตัวไล่จำนวนสาย: เริ่ม 1 → จุดที่ 1: 2 (P, A) → จุดที่ 2 ทุกสาย fork: 4 (P, A, B, B′ โดย B, B′ ได้ค่า 0) → จุดที่ 3 เฉพาะ B, B′ fork: 4 + 2 = 6 → จุดที่ 4 ทั้ง 6 สาย fork: 6 × 2 = 12 ✅ กติกา: จำนวน process เท่าตัว "ต่อจำนวนสายที่ผ่าน fork จุดนั้น" ไม่ใช่เท่าตัวทั้งหมดเสมอ (จุดที่ 3 มีแค่ 2 ใน 4 สายที่ผ่าน!)
C2exit statusเติมตัวเลข
child process เรียก exit(300) — parent ใช้ WEXITSTATUS(status) อ่านค่าที่ได้จริงคือเท่าไร (คำใบ้: exit status ถูกเก็บไว้เพียง 8 บิตล่าง)
เฉลย: 44exit status เก็บได้แค่ 8 บิต (ค่า 0–255) — 300 & 0xFF = 300 mod 256 = 44 — จำหลักไว้: ค่าที่ส่งได้อย่างมีความหมายคือ 0–255 เกินจากนั้นโดน wrap รอบ และอย่าลืมว่าต้องอ่านผ่าน WEXITSTATUS ไม่ใช่พิมพ์ status ตรง ๆ (จะได้เลขใหญ่ผิด ๆ เช่น 32768)
