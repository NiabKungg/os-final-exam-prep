I. Virtual Memory & Page Replacement (OSNo09) 🔥🔥

📖 รู้จักส่วนนี้ก่อนอ่าน

ความหมาย: Virtual Memory (หน่วยความจำเสมือน) = โปรแกรมไม่ต้องอยู่ใน RAM ครบทั้งตัว โหลดเฉพาะเพจที่กำลังใช้ (demand paging) ทำให้ RAM จริงเหมือนใหญ่กว่าจริง · Page Replacement = เมื่อ RAM เต็ม ต้องเลือกเพจ "ตัวปลอด" ออก

ความสำคัญกับข้อสอบ: นับ page fault (เพจยังไม่อยู่ใน RAM) ทั้ง FIFO (เข้าก่อน-ออกก่อน) / Optimal (ดีที่สุดเชิงทฤษฎี) / LRU (รู้ผล 15/9/12 ของ string หลัก), Belady's Anomaly (ปรากฏการณ์เพิ่ม RAM แล้ว fault เพิ่ม), Thrashing (สลับเพจหนักจนระบบแย่) — เป็นแนวคำนวณหลักอีกแนวของ Final

ใช้จริงในคอมพิวเตอร์: เปิดเกมใหญ่กว่า RAM เครื่องได้, สลับแอปเร็วโดยไม่โหลดใหม่, ขนาด "หน่วยความจำเสมือน" ที่เห็นใน Task Manager คือกลไกนี้ — ข้อมูลที่ไม่ได้ใช้ถูกส่งไปพักบน disk

I1. Demand Paging (โหลดเพจเฉพาะเมื่อถูกใช้) — ขอเมื่อไรค่อยเอามา

  • Virtual memory = แยก logical memory ออกจาก physical → address space ใหญ่กว่า RAM จริงก็ได้ · implement ผ่าน demand paging หรือ demand segmentation
  • Demand paging: โหลดเพจเฉพาะเมื่อถูกเรียกใช้ — หลักขี้เกียจของ lazy swapper (ตัวทำงานกับเพจเรียก pager) · ผลดี: I/O น้อย, RAM น้อย, ตอบเร็ว, รองรับ user มาก
  • เพจที่ยังไม่โหลด → bit = i (invalid) → แปลง address เจอ i → Page Fault (เพจยังไม่อยู่ใน RAM) — invalid ที่นี่ส่วนใหญ่ไม่ใช่ error แค่ "ยังไม่มา"

  1. Trap/Interrupt เข้าสู่ OSMMU เจอ bit = i (invalid) → ยิง trap ขึ้น kernel mode
  2. OS ตรวจชนิดของ invalidอ้างเกิน address space จริง → abort · แค่ยังไม่โหลด → ไปขั้นถัดไป
  3. หาเพจบน disk + หา frame ว่างถ้าไม่มี frame ว่าง → ใช้ Page Replacement ก่อน
  4. อ่านเพจจาก disk เข้า frameขั้นที่แพงที่สุด (เป็น I/O ทั้งตัว)
  5. อัปเดต page tableใส่ frame number + เปลี่ยน bit เป็น v (valid)
  6. Restart คำสั่งเดิมCPU รัน instruction ที่พังอีกครั้ง — คราวนี้อ่านได้ปกติ
⚠️ Dirty page

เพจที่ถูกแก้ไข (dirty (เพจที่ถูกแก้ไขข้อมูลแล้ว)/modified = 1) ต้องเขียนกลับ disk ก่อน (write back (เขียนกลับลงดิสก์ก่อน)) ค่อยแทนที่ — เพจ clean (เพจที่ยังไม่ถูกแก้ไข (ดิสก์มีสำเนาแล้ว)) ทับได้เลยเพราะ disk มีสำเนา

I5. EAT เมื่อมี Page Fault Rate (p)

EAT = (1 − p) × memory access time + p × page fault service timeตัวเลขชวนคิด: mat = 200ns, fault service = 8ms → ที่ p = 0.001 (fault แค่ 0.1%) EAT = 0.999×200 + 0.001×8,000,000 ≈ 8,200ns = 8.2μs — ช้าขึ้น 40 เท่า! ห้ามให้ p โต

I6. Global vs Local Allocation

  • Global replacement: แทนที่ได้จาก frame ใดก็ได้ในระบบ — แย่งข้าม process ได้
  • Local replacement: เลือกจากเฉพาะ frame ของตัวเอง (คนละบ้านกับคนละบ้าน)

I7. Thrashing · Locality · Working Set (ชุดเพจที่ต้องมีใน RAM) 🔥

  • Thrashing: process มีเพจไม่พอ → สลับเพจเข้า-ออก disk ตลอดเวลา → CPU utilization ดิ่ง · OS เข้าใจผิดว่า "งานน้อย" เลยเพิ่ม process → thrashing (สลับเพจหนักจนระบบแย่) ยิ่งหนัก (วงจรนรก) · เกิดทั้งข้ามงานและในงานเดียว (ลูปข้ามเพจ)
  • Locality of reference: โปรแกรมมักอ้างกลุ่มเพจเดิมซ้ำ ๆ ในช่วงสั้น ๆ (อยู่ในฟังก์ชัน/ลูปเดิม)
  • Working set: กลุ่มเพจที่ process ต้องมีใน RAM เพื่อไม่ให้ fault ในช่วง locality นั้น — มองย้อนหลัง Δ (working-set window เช่น 10,000 instruction) · WSSᵢ = จำนวนเพจที่ Pᵢ อ้างใน Δ · Δ เล็กไปครอบ locality ไม่หมด / ใหญ่ไปกินหลาย locality / Δ = ∞ คือทั้งโปรแกรม
  • D = Σ WSSᵢ = ความต้องการ frame รวม · ถ้า D > m (frame จริง) → thrashing! → OS ต้อง suspend บาง process คืน frame ให้คนที่เหลือ
🍳 อุปมา

Working set = ของที่ต้องมีบนเคาน์เตอร์เพื่อทำเมนูให้จบ ถ้าวางไม่ครบ คุณวิ่งไปตู้เย็น (disk) ทุก 30 วินาที = ไม่มีอะไรเสร็จ → ทางแก้: ลดจำนวนเมนูที่ทำพร้อมกัน (suspend process)
