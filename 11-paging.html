บทที่ 11 — Paging: สกิลคำนวณที่ตัดสิน "ทันสอบหรือไม่ทัน"

Paging แบ่ง RAM เป็นก้อนเท่า ๆ กันแล้วจับคู่ผ่าน page table — โจทย์เกือบทุกข้อในหัวข้อนี้ถามแค่ 3 อย่าง: (1) หา page/offset จาก address (2) แปลงเป็น physical address (3) คำนวณ EAT กับ TLB — ฝึกให้ไว ให้ได้แต่ละข้อไม่เกิน 1 นาที

1. แนวคิด Paging — ตัด external fragmentation ขาด

Paging คือการจัดสรรหน่วยความจำแบบ non-contiguous (ไม่ต้องติดกัน!):

  • Frame — แบ่ง physical memory (RAM) เป็นบล็อกขนาดคงที่ ขนาดเป็นกำลังสอง 2n bytes (เช่น 512–8,192 bytes ในทางปฏิบัติ)
  • Page — แบ่ง logical memory (โปรแกรม) เป็นบล็อกขนาดเท่า frame เป๊ะ ๆ
  • Page table — ตารางจับคู่ "เพจที่ i ของโปรแกรม อยู่ใน frame ไหนของ RAM"
  • รันโปรแกรมขนาด n เพจ = หา frame ว่าง n อัน กระจายวางก็ได้ (ไม่ต้องติดกันเลย!)
🎯 เช็คความเข้าใจ

Paging ไม่มี External Fragmentation เพราะ frame ว่างอะไรก็ใช้ได้ · แต่ยังมี Internal Fragmentation — เกิดเฉพาะเพจสุดท้ายของโปรแกรมถ้าขนาดไม่ลงตัวกับ page size

2. โครงสร้าง Logical Address — บิต p กับ d 🔥

Address ที่ CPU ปล่อยออกมา (ยาว m บิต) ถูกซอยเป็น 2 ส่วนโดยฮาร์ดแวร์:

ตัวอย่างจากวิดีโอ: Logical address space = 5 บิต (2⁵ = 32 bytes), Page size = 4 bytes:

  1. หา n (บิต offset)4 = 2² → ต้องมี 2 บิตพอสำหรับนับ offset 0–3
  2. หาบิต page numberm − n = 5 − 2 = 3 บิต → เพจได้สูงสุด 2³ = 8 เพจ (เพจ 0 ถึง 7 — นับจากศูนย์!)
  3. ตรวจความสมเหตุสมผล8 เพจ × 4 bytes = 32 bytes ตรงกับขนาดที่โจทย์ให้ ✅
🪑 อุปมาของอาจารย์ (จากวิดีโอ)

ซื้อเก้าอี้มา 32 ตัว จัดใส่ห้อง 8 ห้อง ห้องละ 4 ตัว — เวลาอ้างอิงเก้าอี้ตัวไหน ไม่ได้พูดเลขรวม แต่พูดว่า "ขอเก้าอี้ตัวที่ 3 ในห้องเบอร์ 1" = (Page 1, Offset 3) — สองเลขนี้คือทั้งชีวิตของ Paging!

3. แปลง Logical → Physical Address ทีละขั้น 🔥🔥

Physical Address = (Frame Number × Page Size) + Offsetเปิด page table ด้วย p → ได้ frame → frame คูณ page size = ตำแหน่งเริ่ม frame ใน RAM → บวก offset เข้าไป

โจทย์จากวิดีโอ: Page size = 4 bytes, page table กำหนดว่า:

📍 ตัวอย่างที่ 1: หาตำแหน่งของตัวอักษร 'C' — logical (p=0, d=2)

  1. เปิด page table ด้วย p = 0เพจ 0 อยู่ใน frame 5
  2. นำ offset d = 2 มาใช้ตรง ๆoffset ไม่ผ่านการแปลงใด ๆ
  3. แทนสูตรPA = (5 × 4) + 2 = 20 + 2 = 22 ✅ → 'C' อยู่ที่ byte ที่ 22 ใน RAM

📍 ตัวอย่างที่ 2: หาตำแหน่งของ 'K' — logical (p=2, d=2)

  1. เปิด page table ด้วย p = 2เพจ 2 อยู่ใน frame 1
  2. PA = (1 × 4) + 2= 4 + 2 = 6 ✅
💡 ถ้าโจทย์ให้ address เป็นเลขฐานสอง

แค่ซอยบิต: บิตหลัง (ต่ำ) n ตัว = offset, บิตหน้า (สูง) ที่เหลือ = page number เช่น address 13 ในระบบ 5 บิต/เพจ 4 bytes = บินารี 01101 → p = 011 (3), d = 01 (1) → เปิดตารางด้วยเพจ 3 แล้วบวก offset 1

4. 3 จุดพลาดคลาสสิก (อาจารย์เน้นในวิดีโอ)

  1. บวก frame + offset ตรง ๆ — frame 5, offset 2 แล้วตอบ 5+2=7 ❌ ต้อง (5 × 4) + 2 = 22 ✅ (frame คือ "หมายเลขก้อน" ต้องคูณขนาดก้อนก่อน!)
  2. นับเพจเริ่มที่ 1 — เพจเริ่มที่ Page 0 เสมอ (8 เพจคือ 0–7 ไม่ใช่ 1–8)
  3. ปัดจำนวนเพจลง — โปรแกรม 42 bytes / เพจ 4 bytes = 10.5 → ต้อง ปัดขึ้น 11 เพจ (10 เพจเก็บได้ 40 bytes ข้อมูลขาด!) เพจสุดท้ายใช้จริง 2 bytes → Internal frag = 4−2 = 2 bytes

5. TLB และสูตร Effective Access Time 🔥🔥

เพราะ page table อยู่ใน RAM — เข้าถึงข้อมูล 1 ครั้ง = ไป RAM 2 ครั้ง (1: อ่าน page table หา frame, 2: อ่านข้อมูลจริง) แก้ด้วย TLB (Translation Look-aside Buffer) — แคชฮาร์ดแวร์ความเร็วสูง เก็บคู่ (page # → frame #) ล่าสุด ค้นแบบขนาน (associative)

กรณีไป RAM กี่ครั้งเวลา
TLB Hit (โอกาส α)1 ครั้งค้น TLB (ε) + อ่านข้อมูล (1) = 1 + ε
TLB Miss (โอกาส 1−α)2 ครั้งค้น TLB (ε) + อ่าน page table (1) + อ่านข้อมูล (1) = 2 + ε
EAT = α(1 + ε) + (1 − α)(2 + ε) = 2 + ε − αα = hit ratio · ε = TLB search time · สูตรลัดตัวหลังใช้ได้เมื่อ memory access = 1 μs ต่อครั้ง

โจทย์จากวิดีโอ: ε = 0.1 μs, α = 80%, memory access = 1 μs

  1. กรณี Hit (0.8)0.1 + 1.0 = 1.1 μs
  2. กรณี Miss (0.2)0.1 + 1.0 + 1.0 = 2.1 μs
  3. ถ่วงน้ำหนักEAT = (0.8 × 1.1) + (0.2 × 2.1) = 0.88 + 0.42 = 1.3 μs ✅ (สูตรลัด: 2 + 0.1 − 0.8 = 1.3 — ตรงกัน)

เทียบกับไม่มี TLB เลย = 2 μs ทุกครั้ง → TLB hit 80% ช่วยลดเหลือ 1.3 μs

6. Protection — Valid / Invalid bit

  • แต่ละแถวใน page table มี valid–invalid bit: v (valid) = เพจนี้อยู่ใน address space ของ process (ใช้ได้ตามกฎหมาย) · i (invalid) = ห้ามอ้างอิง
  • Registers ช่วยเฝ้า: PTBR ชี้ตำแหน่ง page table ใน RAM · PTLR บอกความยาวตาราง (ตรวจเบื้องต้นว่าไม่อ้างเพจเกินขอบเขต)
🚨 จุดหลอก: Valid bit ดูแล "ทั้งเพจ" ไม่ได้ดู "ทีละไบต์"

ถ้าเพจสุดท้ายของโปรแกรม 42 bytes มี valid = v ระบบจะยอมให้อ้าง offset ใด ๆ ในเพจนั้น (แม้เกิน 42) เพราะมันเช็คแค่ว่า "เพจนี้เป็นของจริง" — ไม่รู้ว่าโปรแกรมจบที่ offset ไหน นี่คือเหตุผลที่ internal fragmentation ยังอยู่รอดใน paging

7. Two-Level Paging — ทำไมและคำนวณยังไง 🔥

ปัญหา: Page table เปลือง RAM สุดโง่เง่า

ระบบ 32-bit, page size 4 KB (2¹² → offset 12 บิต):

  1. บิต page number32 − 12 = 20 บิต → จำนวนช่อง = 2²⁰ = 1,048,576 ช่อง
  2. สมมติ 1 ช่อง = 4 bytesขนาด page table = 1M × 4B = 4 MB ต่อ process หนึ่ง!
  3. ปัญหาโปรแกรมเล็กแค่ 1 MB ก็ต้องแบก page table 4 MB ให้ทุก process — สิ้นเปลืองมหาศาล (และตารางต้องอยู่ต่อเนื่องใน RAM อีก)

ทางแก้: ซอย page table เป็นสองชั้น (Hierarchical Paging)

ซอยบิต 32 ตัวเป็น 3 ส่วน: p₁ = 10 บิต | p₂ = 10 บิต | d = 12 บิต — p₁ เปิด outer table หาว่า inner table ตัวที่เท่าไร, p₂ เปิด inner table หา frame

ตัวอย่างที่ 1 จากวิดีโอ: โหลดโปรแกรม 1 MB

  1. นับเพจที่ต้องใช้1 MB = 1024 KB ÷ 4 KB/เพจ = 256 เพจ
  2. นับ inner table ที่ต้องสร้าง1 inner table จุ 2¹⁰ = 1024 ช่อง — 256 ช่องใช้ inner แค่ 1 ตาราง
  3. รวมพื้นที่Outer 1 ตาราง (1024 × 4B = 4 KB) + Inner 1 ตาราง (4 KB) = 8 KB ✅ เทียบกับ single-level ที่เสีย 4 MB!

ตัวอย่างที่ 2 จากวิดีโอ: โหลดโปรแกรม 8 MB

  1. นับเพจ8 MB = 8192 KB ÷ 4 KB = 2048 เพจ
  2. inner tables2048 ÷ 1024 = 2 ตาราง
  3. รวมพื้นที่Outer 4 KB + Inner 2 × 4 KB = 12 KB ✅

หมายเหตุ: ยังมีแนวทางอื่นใน handout เช่น Hashed page table และ Inverted page table — รู้จักชื่อพอ

🎯 สรุปสูตรบรรทัดเดียวที่ต้องใช้ทั้งบท
บิต offset = log₂(page size) · บิต page# = บิต address − บิต offset · จำนวนเพจ = ceil(ขนาดโปรแกรม ÷ page size) · PA = frame × pageSize + offset · EAT = 2 + ε − α · inner tables = ceil(จำนวนเพจ ÷ 1024)

✏️ข้อ 4เติมตัวเลข — EAT จากวิดีโอ
