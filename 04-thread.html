1. Thread คืออะไร

Thread = ลำดับคำสั่งที่รันได้อย่างอิสระภายใน process เดียวกัน แต่ละ thread มีของส่วนตัวน้อยนิด (program counter, registers, stack) แต่แชร์ของใหญ่ร่วมกัน (code section, data section, heap, ไฟล์ที่เปิด) กับ thread พี่น้องใน process เดียวกัน

ชื่อเล่น: lightweight process — เพราะสร้าง/สลับ/ทำลายถูกกว่า process มาก (สลับ thread ใช้เวลาน้อยกว่าสลับ process) และ thread คือ หน่วยที่ OS จัดคิวเข้า CPU จริง ๆ ในระบบสมัยใหม่

ทำไมต้องใช้ thread? (เหตุผลของ cooperating processes ก็ใกล้เคียงกัน)

  • เร็วขึ้น / ทำงานขนาน — คำนวณชิ้นใหญ่แบ่งให้หลาย thread ทำพร้อมกัน
  • Responsive — UI ไม่ค้าง (thread หนึ่งรอดาวน์โหลด อีก thread ยังตอบสนองผู้ใช้)
  • ประหยัด — สร้าง/สลับถูกกว่า process
  • แชร์ข้อมูลสะดวก — thread ใน process เดียวกันเห็น heap เดียวกันเลย (ไม่ต้องขอ IPC)

OS แต่ละยุคจัด process/thread ยังไง (ออกจับคู่บ่อย)

ประเภทตัวอย่าง

3. Multithreading Models 🔥

เชื่อม ULT กับ KLT ยังไง — มี 3 โมเดล ออกถูก/ผิดและจับคู่ตัวอย่างบ่อย:

3.1 Many-to-One

Thread ผู้ใช้หลายตัว ถูก map ไปkernel thread ตัวเดียว — เร็วเพราะจัดการฝั่ง user ล้วน แต่ถ้า thread ไหน block เกิด system call ทั้ง process จะหยุดหมด และขนานจริงบนหลาย CPU ไม่ได้ · ตัวอย่าง: Early Unix System

3.2 One-to-One

Thread ผู้ใช้ 1 ตัว = kernel thread 1 ตัว — ขนานจริง ตัวไหน block ตัวอื่นไม่พัง แต่สร้าง kernel thread เยอะมี overhead · ตัวอย่าง: Windows (ตั้งแต่ NT), Linux, Solaris 9+

3.3 Many-to-Many

ผู้ใช้หลายตัว map ไป kernel หลายตัว (ไม่จำเป็นต้องเท่ากัน) — OS สร้าง kernel thread ให้พอดีจำนวน · ตัวอย่าง: Solaris รุ่นก่อน 9, Tru64 UNIX

4. เขียนโปรแกรม: Pthreads (C) และ Java

Pthreads — โครงที่ต้องจำ (จาก handout)

pthread_sum.c (ตัดให้เห็นโครง)
int sum;  // ตัวแปรนี้ "แชร์" ระหว่าง thread!

int main(int argc, char *argv[]) {
    pthread_t tid;              // id ของ thread
    pthread_attr_t attr;
    pthread_attr_init(&attr);   // default attributes
    pthread_create(&tid, &attr, runner, argv[1]);  // สร้าง thread ให้รันฟังก์ชัน runner
    pthread_join(tid, NULL);    // รอ thread จบ (เหมือน wait ของ process!)
    printf("sum = %d\n", sum);
}

void *runner(void *param) {
    int upper = atoi(param);
    sum = 0;
    for (int i = 1; i <= upper; i++) sum += i;
    pthread_exit(NULL);         // จบ thread (เหมือน exit ของ process)
}

จับคู่ความคิด: pthread_create ≈ fork · pthread_join ≈ wait · pthread_exit ≈ exit — แต่ thread แชร์หน่วยความจำกันจริง (sum แก้แล้ว main เห็นเลย)

Java — 2 วิธีสร้าง thread

วิธีที่ 1: extends Thread
class Worker1 extends Thread {
    public void run() {
        System.out.println("I Am a Worker Thread");
    }
}
// ใช้: Worker1 runner = new Worker1(); runner.start();
วิธีที่ 2: implements Runnable (นิยมกว่า — ไม่เผา slot extends)
class Worker2 implements Runnable {
    public void run() {
        System.out.println("I Am a Worker Thread");
    }
}
// ใช้: Thread thrd = new Thread(new Worker2()); thrd.start();
📌 join() คือ "รอฉันก่อน"

task.join(); — main thread จะหยุดรอ task จบก่อน จึงพิมพ์ "Worker done" หลัง"Worker working" เสมอ (เทียบกับ wait() ของ process ในบท 3)

5. Thread Cancellation และ Thread Pool

  • Thread Cancellation = ยุติ thread ก่อนงานเสร็จ มี 2 สไตล์:
    • Asynchronous cancellation — ยิงปิดทันที เสี่ยงข้อมูลกึ่งกลางพัง (คำสั่งค้างครึ่งจบ)
    • Deferred cancellation — บอกเป้าหมายว่า "ควรตายแล้วนะ" แล้วให้เป้าหมายเช็คเองเป็นระยะ (Thread.currentThread().isInterrupted()) แล้วเคลียร์งานปิดอย่างสวยงาม
  • Thread Pool = สร้าง thread เตรียมไว้ใน "บ่อ" ตั้งแต่เริ่ม งานเข้ามาก็หยิบไปใช้ ใช้เสร็จคืนบ่อ — ดีกว่าสร้างใหม่ทุกงาน (เร็วกว่า + คุมจำนวน thread ได้)
    • Java มี 3 แบบ: Single thread executor (บ่อขนาด 1) · Fixed thread executor (ขนาดคงที่) · Cached thread pool (ขนาดไม่จำกัด สร้างเพิ่มอัตโนมัติ)

6. Java Thread Scheduling

  • Java spec ไม่บังคับมาตรฐาน scheduling — แล้วแต่ implementation ของแต่ละ JVM (แต่โดยทั่วไปใช้แบบ preemptive + priority-based)
  • Priority อยู่ช่วง 1–10, default = 5, ตั้งด้วย myThread.setPriority(6); — เลขมาก = สิทธิสูง (ต่างจาก Unix ที่เลขน้อย = สูง!)
  • Thread รันจนกว่า: มีตัว priority สูงกว่ามาแย่ง / เรียก yield() / run() จบ / หมดเวลา time-slice (บนระบบที่มี time-slicing)
  • เส้นทางเดียวกัน (same priority) → scheduler สุ่มเลือก
🎯 ประโยคทองของอาจารย์ (ออกถูก/ผิดได้)

การตั้ง priority ไม่การันตีลำดับการทำงาน 100% — การเขียนโปรแกรมที่ถูกต้อง ห้ามฝากความถูกต้องของ logic ไว้กับ CPU scheduler แต่ต้องควบคุมผ่านกลไก Synchronization (บท 7–8 กำลังรออยู่)
