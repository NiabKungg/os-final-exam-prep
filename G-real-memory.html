G. Real Memory Management (OSNo08 ต้น)

📖 รู้จักส่วนนี้ก่อนอ่าน

ความหมาย: การจัดสรร RAM ให้ process ตอนโหลด (ยุคก่อนมี virtual memory) — จัดแบบช่องคงที่, ช่องแปรผัน, หรือแบ่งตามส่วน (Segmentation (การแบ่งหน่วยความจำตามส่วน)) พร้อมกลยุทธ์เลือกหลุม First/Best/Worst-fit (หยิบหลุมใหญ่ที่สุด)

ความสำคัญกับข้อสอบ: โจทย์ first/best/worst-fit คำนวณเร็วได้คะแนนง่าย + Segmentation (เช็ค offset (ตำแหน่งเลื่อนภายในเพจ) < limit ก่อน แล้วค่อย base + offset) — และการแยก internal/external (ภายนอก (กระจายเป็นหลุม)) fragmentation (การแตกเป็นเศษพื้นที่) ให้ถูกตัว

ใช้จริงในคอมพิวเตอร์: เป็นต้นแบบ memory allocator (malloc/free) ในทุกภาษา · ปัญหา fragmentation ยังพบจริงในระบบฝังตัว (embedded) และการจัดการหน่วยความจำ GPU

G1. Logical (เชิงตรรกะ (มองจากโปรแกรม)) vs Physical Address (ที่อยู่จริงใน RAM) + MMU

Logical (Virtual) AddressPhysical Address
สร้างโดยCPU ปล่อยขณะรันตำแหน่งจริงที่ memory unit มองเห็น
จุดอ้างอิงโปรแกรมเริ่มที่ byte 0 เสมอเทียบจุดเริ่ม RAM จริง

MMU = ฮาร์ดแวร์แปลง logical (เชิงตรรกะ (มองจากโปรแกรม)) → physical (เชิงกายภาพ (ตำแหน่งจริง)) แบบง่ายสุดคือบวก Relocation (Base) Register

Physical Address = Relocation Register (รีจิสเตอร์เก็บตำแหน่งฐาน) + Logical Address (ที่อยู่เชิงตรรกะ (มองจากโปรแกรม))ตัวอย่างวิดีโอ: โปรแกรมโหลดที่ 14,000 · CPU ขอ byte 346 → PA = 14,000 + 346 = 14,346

G2. Static vs Dynamic Linking (มีตัวเลขให้คำนวณ)

  • Static linking: ก๊อปโค้ด library รวมใน executable ตั้งแต่ compile — lib ซ้ำทุกโปรแกรม
  • Dynamic linking: เลื่อนไป link (ลิงก์ (ทางเชื่อม)) ตอน run — ใส่แค่ stub (โค้ดจิ๋วหา library / แทนตัวเองด้วย address routine) → library โหลดครั้งเดียวแชร์กันทั้งระบบ (shared libraries)
ตัวอย่างวิดีโอ: A(10MB) + B(20MB) + Lib(20MB)
Static: A=30MB, B=40MB → RAM 30+40 = 70MB (lib ซ้ำ 2 ชุด)
Dynamic: A=10+2, B=20+2, lib 1 ชุด → 12+20+22 = 54MB ประหยัด 16MB

G3. Fixed Partition — Internal Fragmentation (เศษภายในช่องที่จองแล้ว)

  • แบ่ง RAM ส่วน user เป็นช่องคงที่ล่วงหน้า → มีกี่ช่องรับ process พร้อมกันได้เท่านั้น · ป้องกันด้วย limit register (ขนาด) + relocation register (ตำแหน่ง): เช็ค LA < Limit ผ่านแล้วค่อย + Base
  • ตัวอย่างวิดีโอ: Partitions P1=100K, P2=25K, P3=25K, P4=50K · Job1(30K)→P1 (เหลือ 70K ใช้ไม่ได้ = internal frag) · Job2(50K)→P4 พอดี · Job3(30K) ต้องรอ! เพราะ P2,P3 มีแค่ 25K แม้ว่างรวม 120K · Job4(25K)→P2 พอดี
🎯 คู่แฝด fragmentation

Fixed = Internal (เศษในช่องจองแล้ว ใครใช้ต่อไม่ได้) · Variable + Segmentation = External (เศษกระจายนอก รวมว่างเยอะแต่ช่องเดียวไม่พอ) · Paging = ไม่มี External แต่มี Internal ที่เพจสุดท้าย — ออกถูก/ผิดวนไป

G4. Variable Partition — External Fragmentation (เศษกระจายนอก (หลุมเล็ก ๆ)) + วิธีรักษา

จัดสรรตามขนาดจริง ตอนแรกไม่มีของเสีย แต่งานจบทิ้งช่องว่างกระจาย · ตัวอย่าง: หลุมว่าง 5+2+1 = 8MB แต่ขอ 7MB โหลดไม่ได้ (ช่องเดียวใหญ่สุด 5MB)

วิธีรักษาทำอะไรข้อจำกัด
Coalescing (การรวมหลุมว่างที่ติดกัน)รวมหลุมที่ติดกันเป็นหลุมใหญ่ 1 หลุมหลุมไม่ติดกันก็ช่วยไม่ได้ — มักไม่พอ
Compaction (การอัดข้อมูลให้ติดกัน)ลาก process มาอัดติดกัน รวมว่างปลายเดียวoverhead แพง และทำได้เฉพาะ relocation แบบ dynamic (ตอน execution time)

G5. First-fit (หยิบหลุมแรกที่พอ) · Best-fit (หยิบหลุมที่แน่นที่สุด) · Worst-fit 🔥 (ตัวอย่างจากวิดีโอ)

โจทย์ (สไลด์ p.21–24): หลุมเรียงตามลำดับใน RAM: 16, 14, 5, 30 MB · process ใหม่ต้องการ 13 MB

กลยุทธ์หลักคิดลงหลุมเศษเหลือจุดเด่น/ด้อย
First-fitไล่จากซ้าย เจอหลุมแรกที่ ≥ ขนาด เอาทันที163เร็วสุด (ไม่สแกนครบ) แต่เปลืองพื้นที่
Best-fitสแกนครบ เลือกหลุมที่ "ใหญ่พอ + เหลือน้อยสุด"141คุ้มสุด แต่ช้า + ทิ้งเศษจิ๋วใช้ต่อไม่ได้
Worst-fitสแกนครบ เลือกหลุมใหญ่สุด3017ทิ้งชิ้นใหญ่ให้งานต่อไป (โดยรวมมักแพ้ best-fit)

G6. Segmentation 🔥 — แบ่งตามสายตาโปรแกรมเมอร์

  • แบ่งเป็น logical unit ขนาดไม่เท่ากัน: main, function, object, stack, global variables · Logical address = คู่ <segment s, offset d>
  • Segment table แต่ละแถวมี Base (จุดเริ่มใน RAM) + Limit (ความยาว) · STBR ชี้ตาราง, STLR = จำนวน segment (s ใช้ได้ถ้า s < STLR)
ขั้นแรก: เช็ค d < Limit — ถ้า d ≥ Limit → TRAP (error!) ทันที
ขั้นต่อมา: Physical Address = Base + Offset (ตำแหน่งเลื่อนภายในเพจ)

ตัวอย่างจากสไลด์ p.50: S1 (base 6300, limit 500) · S2 (base 4300, limit 400)

🎯 จุดหลอก

เช็ค ก่อนเสมอ แล้วค่อยบวก — เคร่งครัดเรื่อง < ไม่ใช่ ≤ · Segmentation ยังเจ็บกับ external fragmentation (แต่ละ segment ต้องวางติดกันเป็นผืน) · สูตรอย่างสลับกับ paging (การแบ่งหน่วยความจำเป็นหน้า): Segment/Base = Base + offset / Paging = frame (เฟรม (ก้อน RAM)) × size (ขนาด) + offset
